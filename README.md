# 葫洲美好際寓 水電分帳試算

透天厝分租套房（6 間房：3A、3B、4C、4D、5E、6F）的水電費分帳計算工具。每期收到台水、台電帳單後，用這個工具算出每間房該繳多少錢，並一鍵產生可直接貼到 LINE 群組的通知文字。

計算邏輯完全比照房東提供的「水電費分攤試算表.xlsx」，兩邊試算結果經過逐項核對，完全一致。

線上使用：https://roommate-utility-calculator.streamlit.app/

---

## 這個工具在做什麼

每期要處理兩張各自獨立的帳單：

- **台水帳單**：基本費 + 用水費 + 水源保育與回饋費，依「計費期間」分攤。
- **台電帳單**：依各房電表的用電度數分攤，剩下的公共用電（走廊燈、抽水馬達等）再依規則分給各房。

水費和電費是不同單位、不同抄表週期，計費區間各自獨立輸入，不需要對齊。

## 計算邏輯

以下規則都對照房東 Excel 的公式校準過，`tests/test_calculator.py` 裡的
`TestExcelParityWaterExample`、`TestExcelParityElectricityExample` 直接拿房東試算表算過的真實數字驗證，兩邊结果逐元對上。

### 房間基本資料（`config/rooms_config.json`）

每間房記錄以下欄位（對應房東 Excel「房客資料」工作表）：

| 欄位 | 說明 |
|---|---|
| `contract_date` | 簽約日 — 用於**電費**的公電分攤天數計算 |
| `move_in_date` | 實際入住日 — 用於**水費**的入住天數計算 |
| `move_out_date` | 退租日 — 目前都設在約一年後，代表尚未退租 |
| `headcount` | 入住人數（1 或 2） |
| `initial_reading` | 電表度數的**預設**起始值 — 每期實際計算時，表單上的「起始度數」可以覆蓋這個值（見下方「跨期延續使用」） |

簽約日跟實際入住日是兩個不同的日期（房客通常先簽約，才實際搬進來），水費跟電費各自用不同的日期起算，不要混用。

### 水費計算

1. **基本費**：先把總基本費平均分成 6 份，每房再依「該房在計費區間內的入住天數」佔「計費區間總天數」的比例分攤。未入住的天數對應的基本費由房東吸收。

   ```
   每房基本費 = (總基本費 / 6) × (該房入住天數 / 計費區間總天數)
   ```

2. **用水費 + 水源保育與回饋費**：兩者相加後，依「人數 × 入住天數」的權重比例分攤。

   ```
   權重 = 入住人數 × 入住天數
   該房用水相關費 = (用水費 + 水源保育費) × (該房權重 / 全部房間權重總和)
   ```

3. **入住天數**：計費區間**頭尾皆計**（`結束日 - 起算日 + 1`）。起算日是「實際入住日」與「水費計費起始日」兩者較晚的一個；若在計費區間內退租，結算日改用退租日。

4. **房東吸收金額**：不是加總每房的「未入住天數基本費」，而是直接用

   ```
   房東吸收 = 水費帳單總額 - 各房水費（四捨五入後）加總
   ```

   這樣無論怎麼四捨五入，「室友應繳總額 + 房東吸收」一定精確等於帳單總額。

### 電費計算

1. **自家電費**：每房的（期末度數 − 起始度數）× 每度電價。電價是直接輸入台電帳單上的費率，不是用總電費除以總用電度數反推。

2. **公電（公共用電）分攤**：總電費扣掉所有房間的自家電費後，剩下的部分依「人數 × 電費計費天數」的權重分攤。

   ```
   公電 = 本期總電費 - 所有房間自家電費加總
   權重 = 入住人數 × 電費計費天數
   該房公電分攤 = 公電 × (該房權重 / 全部房間權重總和)
   ```

3. **電費計費天數**：跟水費的算法不同——**不是頭尾皆計**，而且是用「簽約日」而不是「實際入住日」起算：

   ```
   若 電費計費起始日 >= 簽約日：
       電費計費天數 = 電費計費結束日 - 電費計費起始日
   否則（簽約日在計費期間中途才開始）：
       電費計費天數 = 電費計費結束日 - 簽約日
   ```

4. 電費沒有「房東吸收」的概念——電費 100% 由房客負擔（自家電費 + 公電分攤），也不會強制校正加總誤差（跟房東 Excel 的行為一致）。

### 四捨五入規則

所有最終金額都四捨五入到**整數元**（無條件依四捨五入，比照 Excel 的 `ROUND(x,0)`，跟 Python 內建 `round()` 的銀行家捨入不同，`src/calculator.py` 裡的 `_round_half_up()` 專門處理這個差異）。

- 水費：基本費和用水相關費「先加總、再一次捨入」，不是分別捨入後再加。
- 電費：自家電費和公電分攤「先加總、再一次捨入」。

### 跨期延續使用（不用每期改程式碼）

- **電表起始度數**：表單上每間房都有「起始度數」欄位，會**自動帶入歷史紀錄裡最新一期的期末度數**（沒有歷史紀錄時才退回 `rooms_config.json` 的預設值），數字不對可以直接覆蓋，不需要改設定檔。
- **房客異動**：表單最上面有一個平常收合的「房客異動」區塊，展開後可以個別調整每間房的簽約日、入住日、退租日、人數。只有真的有人搬進搬出時才需要打開來改，其餘每期不用動。
- 需要真的改 `config/rooms_config.json` 的情況只剩：房號本身增減（例如整棟隔出新房間），這種情況非常少見。

### 歷史紀錄

app 頁面最上方跟最下方都有「歷史紀錄」區塊：

- **每次送出試算**，那一期的完整輸入與結果都會自動記進當次瀏覽階段的歷史清單。
- 頁面最下方可以**下載歷史紀錄（JSON）**，把目前累積的所有期數存成一個檔案。
- 頁面最上方可以**上傳先前下載的 JSON 檔**，之前算過的期數就會全部帶回來，跟這次新算的合併在一起（用「水費 + 電費計費區間」四個日期當作同一期的判斷依據，同一期重算會覆蓋更新，不會重複累加）。

**Streamlit Cloud 是無狀態的**，app 重新部署或閒置太久重啟時，伺服器上的資料會全部清空——這是免費方案的限制，沒有接資料庫。所以歷史紀錄不會自動永久保存，**每次算完都要記得下載存檔**，下次開始使用前先把上次的檔案上傳回來即可接續。

（曾經試過用 `streamlit-javascript` / `streamlit-local-storage` 把歷史紀錄自動存進瀏覽器的 localStorage，讓下次打開不用手動上傳。但這兩個套件在目前的 Streamlit 版本下元件回傳值會卡住甚至讓伺服器沒回應，穩定性風險太高，已經移除，改回純手動下載/上傳。）
